# Worked examples

Both methods below are fictional teaching inputs. `method.md` is the source; `visual-schema.json` links nodes and connections to exact excerpts. The compiled prompts are generated files, not separately maintained blueprints.

| Example | What it exercises | Files |
| --- | --- | --- |
| Dual stream | Independent RGB/depth encoders, specified concatenation, shared prediction path, training-only alignment loss | [method](dual-stream/method.md), [schema](dual-stream/visual-schema.json), [prompt](dual-stream/renderer-prompt.md) |
| Iterative | Fixed observation, initial state, inference-time state update, explicit curved return and stop-after-K edge | [method](iterative/method.md), [schema](iterative/visual-schema.json), [prompt](iterative/renderer-prompt.md), [editable preview](iterative/preview.svg) |

The preview is a manually constructed SVG following the iterative schema, not generated by an image model. Its visible labels and directed connections match the blueprint. It demonstrates the intended topology, not renderer quality or convergence.

Suggested iterative caption: **Iterative state update.** A fixed observation and the current state enter an update block. The resulting state returns to the register for the next iteration; after K updates, the last state is returned as the estimate. The schematic describes inference and leaves the update operator unspecified.

Suggested dual-stream caption: **Dual-stream classification.** Separate encoders produce RGB and depth features, which are concatenated and classified. An alignment loss consumes both features during training and is omitted during inference. The schematic specifies neither shared weights nor gradient routing.

Rebuild prompts from the repository root:

```bash
python3 scripts/schema_tool.py compile examples/dual-stream/visual-schema.json --output examples/dual-stream/renderer-prompt.md
python3 scripts/schema_tool.py compile examples/iterative/visual-schema.json --output examples/iterative/renderer-prompt.md
```
